# 지하철/트램 운행 시뮬레이션 — 데이터 출처와 계산식

시뮬레이션에 쓴 숫자가 어디서 왔고 어떤 식으로 계산했는지 정리. 코드 안
주석에 흩어져 있던 걸 한 곳에 모은 것 — 원본 근거는 괄호 안 파일 경로 참고.

## 지하철(1호선)

### 역/노선 데이터
- **역 목록·좌표·역간 거리**: KRIC(한국교통안전공단) 레일포털 역 정보
  조사서 xlsx (`build_subway_data.py`) → `daejeon_subway_stations.geojson`
- **실제 선형(열차가 다니는 궤도)**: OSM에 "대전 도시철도 1호선"으로 태그된
  railway=subway way 3개. 56점+101점짜리가 끝점이 정확히 맞닿아서 이어붙이면
  판암→반석 한쪽 선로(`toBanseok`), 나머지 183점짜리는 역 순서 거꾸로
  스냅해도 단조증가해서 반대쪽(반석→판암) 선로임을 확인(`toPanam`).
  (`build_subway_line_shape.cjs`)

### 역간 소요시간
- **출처**: 대전역 안내판 "역간 소요시간" 사진(사용자 제공) — 대전역 기준
  역별 누적 소요시간(분)을 판암역 기준으로 환산.
- **검증**: 공식 요약표(편도 20.5km, 소요시분 40분)와 "판암~대전 6분 +
  대전~반석 34분 = 40분"으로 정확히 일치해서 신뢰.
- 결과를 `offsetFromPanamMin`/`offsetFromBanseokMin`로 각 역에 저장
  (`build_subway_timing.cjs`).
- 거리 비례 추정치와 비교해 최대 ±0.7분 차이 — 실제 속도가 역간 균일하지
  않다는 걸 보여줄 뿐 데이터 오류 아님.

### 배차간격(배차표)
- **출처**: KRIC 열차 시각표 xlsx(실제 전체 구간을 뛰는 "반석(칠성대)"/
  "판암(대전대)" 발차 기록만 사용 - 정부청사/서대전네거리/구암발 단거리
  임시 운행은 제외해서 배차간격이 실제보다 촘촘하게 나오는 걸 방지).
- 요일별(평일/토요일/휴일)로 시발시각을 정렬해서 연속 간격(gap)을 구하고
  평균/최소/최대 배차(분), 운행 횟수, 첫차/막차 시각 계산
  (`build_subway_timetable.py` → `daejeon_subway_route.geojson`
  `properties.headway`).
- 공휴일 구분은 없음(평일/토요일/휴일 3종만) — 달력 연동 안 됨, 알려진 한계.

### 시뮬레이션 공식
- 열차 위치 = 출발~도착역 사이 **시간 비율**로 실제 선형(`toBanseok`/
  `toPanam`) 위를 보간 (거리 비례가 아니라 실제 역간 소요시간 비례).
- 배차는 요일별 `avgHeadwayMin`을 그대로 써서 등간격으로 열차를 배치.

## 트램(2호선, 공사 중 — 아직 개통 전)

### 역/노선 데이터
- **역 위치·순서**: 공식 데이터 없음 — 사용자가 직접 만든
  `daejeon_tram.gpkg`(GeoPackage, EPSG:5186)를 변환 (`build_tram_data.cjs`).
  "(직접 제작)"으로 라벨링.
- **실제 선형**: OSM에 이미 올라온 **공사 중** 선형. railway=construction +
  construction=tram 태그, 이름별로 본선("대전 도시철도 2호선")/
  연축지선/진잠지선 구분. 역간 그래프를 만들어 다익스트라로 최단경로
  추적(버스전용차로 공식구간 스크립트와 같은 패턴). 끝점이 20m 이내로
  어긋난 곳은 이어붙임 (`build_tram_line_shape.cjs`).
  - 전에는 OSRM 도로 스냅(차량 도로망 기준)을 썼는데, 트램 전용궤도라 실제
    도로망과 다른 구간에서 노선을 벗어나는 문제가 있어서 OSM 선형 기반으로
    교체함.
- **분기점 검증**: 진잠지선 분기점이 "관저(건양대병원)"이 아니라
  "관저네거리"인 걸 거리로 확인(관저네거리→진잠네거리 1094m ≈ 공식 1.0km,
  관저→진잠네거리 1733m는 안 맞음).
- **기점/종점**: 위키백과 확인 — 본선 서대전역↔서대전역(순환), 연축지선
  **용전역**↔연축역(중리역 아님 — 본선 한 정거장을 같이 타고 중리에서
  갈라짐), 진잠지선 관저네거리역↔진잠네거리역.
- **차량기지 위치**: OSM에 `service=yard`로 태그된 선형의 중심점이
  **정부청사역에서 65m**(가장 가까운 역) — 그래서 본선 순환열차는
  정부청사역을 출고 기준점으로 삼음(서대전역 아님).

### 운행시간·배차간격·속도 (공식 발표 자료, 사용자 제공)
- 운행시간: 05:30 ~ 익일 00:30
- 배차간격: 본선 첨두 8분 / 비첨두 10.67분, 지선 10.67분
  (첨두시간: 07~09시, 18~20시)
- 표정속도(정차시간 포함): **22.06km/h** — 대전시 발표 자료 인용(토론토
  15km/h·암스테르담 16·파리 17·스트라스부르크 21km/h보다 빠르다는
  언론 보도 포함). 원문 링크는 사용자가 채팅으로 전달(저장된 파일 없음).
- 승차정원 225인(혼잡시 최대 305인), 기본 34편성, 무가선 수소연료전지
  급전 방식.
- 노선: 본선 33.9km(서대전역~대전역~대동~정부청사~유성온천~서대전역
  루프), 연축지선 3.9km(중리~법동~동부여성가족원~연축), 진잠지선
  1.0km(관저~진잠) — 출처: daejeon.go.kr/djTram 사업개요.

### 시뮬레이션 공식
- **역간 소요시간**: 공식 거리·속도 숫자를 그대로 쓰지 않고, OSM 실제
  선형을 이어붙인 뒤 실측 거리(km) ÷ 22.06km/h × 60으로 역산. 지선 기점이
  바뀌어도(예: 연축지선 용전역 추가) 자동으로 다시 맞음.
- **대수 계산**(표준 배차 공식): `필요 대수 = 한 바퀴(왕복) 도는 시간 ÷
  배차간격`, 반올림.
  - 본선(루프): 주기 = 한 바퀴 전체 시간. 상행/하행 각각 따로 계산해서
    합산.
  - 지선(왕복 셔틀): 주기 = 편도 시간 × 2(갔다 오는 왕복).
  - 예시(08시, 첨두): 본선 11대×2방향=22 + 연축 2 + 진잠 1 = **25대**.
    (공식 "기본편성 34편성"은 보유 전체 차량 수로, 정비·예비차 포함 —
    동시에 전부 운행한다는 뜻 아님.)
- **열차 진입**: 서비스 시작(05:30) 시각에 1호차만 출발, 이후
  `05:30 + k×배차간격`마다 한 대씩 순서대로 출발(처음부터 노선 전체에
  흩어져 있지 않음).
- **순환/왕복 방식**: 본선은 한 바퀴 돌면 그대로 다음 바퀴로 이어지는
  영구 순환, 지선은 끝까지 갔다가 그대로 거꾸로 돌아오는 영구 왕복.
  "상행/하행이 각각 반대 방향으로 영구 순환"하는 구조는
  https://dj2-tram.pages.dev/ (부제목에 "대외비"라 표기, 좌표 데이터는
  긁어오지 않고 이 구조적 사실만 참고)에서 "상행/하행 각 17편성" 서술을
  보고 반영.
- **정차(dwell)**: 역 도착 시 구간 시간의 최대 0.3분(또는 구간의 40%,
  둘 중 작은 쪽)만큼 역 좌표에 멈춰 있다가 출발 — 지하철과 같은 로직 재사용.
  표정속도 자체가 이미 정차시간을 포함한 평균이라, 이 멈춤은 전체
  소요시간을 안 늘리는 시각적 보너스.

## 알려진 한계(아직 확인 안 된 부분)
- 지선 턴백/단축운행 패턴(공식 다이어그램 없음 — 전부 완주한다고 가정).
- 지선 열차가 차량기지에서 바로 들어오는지, 자체 유치선이 있는지 불명 —
  지금은 지선 첫 역(용전/관저네거리)에서 바로 출발하는 걸로 단순화.
- 진잠지선처럼 왕복주기(6.2분)가 배차간격(10.67분)보다 짧은 경우, 실제론
  종점에서 대기해야 하는데 지금 로직엔 대기시간이 없음(배차가 실제보다
  촘촘해 보일 수 있음).
- 지하철 요일 구분은 평일/토요일/휴일 3종뿐, 공휴일 캘린더 연동 없음.
